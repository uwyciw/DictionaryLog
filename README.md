一、实现原理：
    1、将每一条日志分为两部分——字符域和参数域。字符域是日志的文本部分，包括所以的字母和要格式化输出的限定符。
    2、使用编译选项，将字符域存放在一个指定的区域（为节省空间，可以是单片机的flash范围外，因为这部分内容在运行时，是不需要的），且将字符数组的首地址作为日志的索引值。
    3、打印一条日志时，会存储一个固定的日志头。日志头包含有该条日志的索引值，用于后期解析脚本匹配对就应的字符域。这样操作的好处是，无论一条日志的文本信息有多大，打印一条日志时，存储到flash中的数据，只需要有一个日志头大小就可以了。
    4、如果一条日志有参数，则会将参数以数值的形式，存储在日志头的后面；同时，日志头里会保存本日志头后面跟随的参数数目。每个参数所以占用的空间将是固定的。以数值形式存储参数，同样可以起到节省空间的效果。
    5、解析日志时，脚本会根据日志头里的索引，找到对应的字符域；如果有参数，也会将参数附到字符域后面。这样就还原了原本的日志，随后使用打印函数，就可以打印出一条完整日志了。

二、编译器特性：
    1、IAR：
        a、字符域的地址区间，需要符合Cortex-M的区间映射标准，即0x00000000~0x1FFFFFFF之间。
        b、在ELF文件中，字符域的名称与icf文件里，定义的区间名称不同。而是使用"P1/P2/P3"一类的名称，例程中使用的是"P3"。
    2、GCC/KEIL：
        a、字符域的地址区间，可以由用户指定，范围未发现约束条件。
        b、在ELF文件中，字符域的名称与ld文件里，定义的区间名称相同。
